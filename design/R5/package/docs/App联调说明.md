# R5 实体机与 App 联调说明

App 由甲方负责。本文件告诉乙方：App 怎样连 R5、需要乙方在 BLE 接口里提供什么、怎样用开发板做联调。

## 结论

| 运行方式 | 能否控制 R5 | 说明 |
|---|---|---|
| 安卓手机 Chrome 打开网页版 | **可行** | 已按台架固件的蓝牙协议做好连接模块和联调页，仿真联调 19 / 19 通过，待开发板实测。首发用这种方式 |
| 电脑 Chrome / Edge | 可行 | 适合开发时联调 |
| 安卓 App 外壳 | 目前不行 | 外壳里没有网页蓝牙，要加原生蓝牙桥接（约 3–5 个工作日），由甲方决定是否做 |
| iPhone | 不行 | iOS 不支持网页蓝牙，需要原生 App；首发只做安卓 |

## 台架固件的蓝牙协议

| 服务 / 特征 | UUID | 属性 | 格式 |
|---|---|---|---|
| 电池服务 / 电量 | `0x180F` / `0x2A19` | 读、通知 | 1 字节，0–100 |
| R5 服务 | `5a0e5000-7e4b-4c1e-9c2a-52355f425231` | | |
| 输出模式 | `5a0e5001-…` | 读、写、通知 | 1 字节：0 耳机，1 外放，2 蓝牙耳机，3 外放 + 蓝牙 |
| 参数 | `5a0e5002-…` | 读、写、通知 | 4 字节，各 0–100：音量、音色、效果、伴奏比例 |

设备广播名以 `SmartVio-R5` 开头；广播里只带电池服务。固件在任一项改变后约 50 ms 把输出和参数两项一起回传。协议的实现见台架固件源码 `main/ble.c`。

## 正式 BLE 接口要求（乙方在阶段 3 中期交接口文档）

至少包括：

1. 输出：耳机 / 线路 / 外放 / 蓝牙耳机（台架固件的编码里没有“线路”）；
2. 音量、音色、效果、伴奏比例；
3. 电量、是否在充电、低电提醒；
4. 调音器读数（音名和音分偏差）的通知；
5. 最大音量限制的开关；
6. 固件版本（建议用标准设备信息服务 `0x180A`）和故障代码。

旋钮、按键和 App 改的是同一组数值，任何一方改了都要通知 App。

## 用开发板联调（约 30 分钟）

需要：ESP32-S3-DevKitC-1 开发板一块、安卓手机（装好 Chrome）、台架验证固件（`04-固件/R5-ESP32-S3台架验证固件/`，不接编解码器也能运行蓝牙）。

1. 按固件说明用 esptool 把台架固件烧进开发板，串口能看到 `ready`。
2. 手机 Chrome 打开甲方提供的联调页（`/r5-device.html`，必须 HTTPS）。
3. 点“搜索并连接”，选 `SmartVio-R5-bench`，电量显示 87 %（台架固件的假数据）。
4. 点“开始自动联调”，19 项应全部通过，往返时间平均 200 ms 以内。
5. 在串口输入 `vol 40`、`out spk`，页面数值应在 1 秒内跟着变。
6. 点“复制联调记录”，发给甲方存档。

安卓 11 及以下要先打开手机定位，安卓 12 及以上要允许 Chrome 的“附近设备”权限，否则搜不到设备。
